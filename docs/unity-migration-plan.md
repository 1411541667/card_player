# 网页端到 Unity 端迁移计划

## 目标

Unity 原生版以网页端 `src/game` 的 `GameKernel` 为唯一规则基线。相同内容包和 seed 下，两端应产生相同的地图、战斗结果、奖励、事件和存档状态。

## 当前基线（2026-09-09）

- 网页端：完整 TypeScript 规则核心、Phaser 地图/战斗渲染、Preact UI、`RunSaveV2` 存档。
- Unity 端：内容 JSON 已接入；`NativeGameSession` 仍是简化规则；IMGUI 已覆盖菜单、地图、战斗、奖励、商店、事件、休整、结果、百科和设置。
- 主要缺口：开局祝福流程、真实地图生成、完整卡牌/状态/触发器、数据驱动事件和商店、遗物与收藏品、双端随机数一致性、`RunSaveV2` 兼容、正式 UGUI 表现。

## 里程碑

1. **规则基线**：建立 C# 领域模型、命令分发、事件日志、快照和命名空间随机数。
2. **流程对齐**：迁移角色/祝福/删牌/主题、地图节点和楼层推进。
3. **战斗对齐**：迁移卡牌效果、资源、状态、敌人意图、精英和首领。
4. **节点对齐**：迁移事件、商店、休整、奖励、遗物和收藏品。
5. **存档对齐**：支持 `RunSaveV2` 导入导出。旧 `NativeRunSave` 缺失完整规则状态，须单独设计兼容边界，不能承诺无损转换。
6. **表现层**：将 IMGUI 替换为 UGUI/UI Toolkit，并实现地图与战斗视觉反馈。
7. **验收发布**：同 seed 回放比对、性能检查、IL2CPP Windows 构建和安装包验证。

## 每个里程碑的验收方式

- 规则层必须有 Unity EditMode 测试。
- 使用固定 seed 执行相同命令序列，比较网页端和 Unity 端的快照/事件。
- 内容只从 `unity/Assets/StreamingAssets/wasteland/data` 加载，源数据继续由根目录 CSV→JSON 流程生成。
- UI 不直接修改规则状态，只发送命令并消费快照。

## 已实施的基础工作

- `NamespacedRandom.cs`：移植网页端 UTF-16 hash、32 位采样、整数抽样与洗牌；导出/恢复各随机流计数。
- `NativeGameSession` 已接入该算法，使用临时 `native:*` 随机流；这不代表地图、战斗、奖励已与网页端一致，完整规则迁移时还需对齐命名空间及调用顺序。
- 原生存档升级到 schema 2，保存抽牌堆、弃牌堆和随机状态。此格式仍是 **NativeRunSave**，不是网页端 **RunSaveV2**。
- 旧 schema 1 可恢复已有字段并重建手牌之外的牌堆，但无法恢复原始顺序或随机状态。
- 添加网页端数值参考测试（包括中文及 emoji seed）、随机状态 JSON 往返测试、战斗读档后连续回合一致性测试。

## 第二批：开局与地图（已实施）

- `RouteModels.cs`：开局状态、卡牌实例（独立 ID/升级等级）、地图节点和连接模型。
- `RouteGenerator.cs`：逐步移植网页地图生成算法，保留随机流命名与调用顺序、稳定排序，以及 JavaScript 的四舍五入方式。
- 前三层按照内容规则生成 60–72 个节点，第四层固定为真相事件、商店和首领。节点定义读取 `nodes.json`，不再依赖新局的固定地点轮换。
- 新局增加角色 → 三选一祝福 → 可选删牌/开局商店 → 主题 → 地图流程。两名角色的初始牌组、初始收藏品、六项祝福的初始状态均与网页参考数据比对。
- 最高等级强化使用独立卡牌实例，基础伤害/防护/抽牌/费用读取对应升级定义；完整效果执行器仍待迁移。
- 地图入口校验可达性，记录当前节点、已访问节点和下一行可选节点；普通奖励回到本层地图，首领奖励才进入下一层。
- IMGUI 增加祝福、删牌、主题和可滚动节点表，显示下一行连接。此界面用于操作迁移后的规则，尚未实现正式地图美术、连线渲染和 UGUI。
- 原生 `NativeRunSave` 升级为 schema 3，保存开局过程、地图、实例升级、收藏品和每回合资源；schema 1/2 继续使用原有简化路线，不伪造旧局的完整地图。该格式仍不等于网页 `RunSaveV2`。
- 修复退出结算页后仍可继续已结束探索的状态判断。

## 第三批：可重复验收、战斗与奖励（已实施）

### 用户验收入口

- 操作步骤见 [Unity 测试说明](unity-testing.md)。
- `powershell -ExecutionPolicy Bypass -File .\scripts\test-unity.ps1`：检查网页参考数据及两端内容 → Unity EditMode → 输出 XML/日志路径和通过数量。
- 脚本仅管理自己创建的批量测试进程，处理测试完成后进程退出卡住的问题；不结束用户编辑器、不读写个人存档。

### 战斗同步范围

- `encounters.json` 遭遇池、第一层开局敌人限制、优先选择未遭遇敌人、多敌人生成；每名敌人保留生命、护盾、状态和意图序号。
- 按 `enemies.json` 轮换执行攻击、回血、防护和攻击后自我防护；加入 UI 目标选择和意图名称显示。
- 抽牌改为从牌堆末尾抽取，并对齐初始洗牌、回合洗牌、手牌上限和效果执行顺序。
- 读取完整卡牌效果与升级效果：愤怒首击翻倍、潜伏攻击免费次数、虚弱持续时间、强壮/锋利/清晰、资源增减、消耗区。
- 接入当前收藏品的战斗触发：攻击回血、完全格挡加强壮、每十次抽牌获得资源、战斗开始加状态、胜利回血和金币随机倍率。
- 普通战斗随机金币、精英固定 100 金币；非最终首领奖励、最终首领直接结算。
- 新战斗的进入、出牌、结束回合及领取奖励使用快照回滚：非法目标、资源不足或效果失败不扣费、不消耗随机状态。
- `NativeRunSave` schema 4 保存敌人意图、状态持续时间、各资源、消耗区、战斗计数、随机状态和奖励候选；schema 1–3 的旧战斗保持原有规则继续。

### 奖励同步范围

- 奖励节点执行网页相同的随机池洗牌及单项抽取。
- 首领按 encounter 的 rewardPool 生成候选，UI 使用内容名称。
- 金币、百分比回血、卡牌、收藏品、收藏品首次获得时的随机强化；重复收藏品不重复执行获得效果。
- 新卡牌实例 ID 使用牌组长度与当前修订号；非最终首领奖励重新生成下一层地图。

### 验证与限制

- 一键脚本实测 **27 项 Unity EditMode 测试通过**。网页基准包含 16 组地图、12 组开局、9 场完整战斗的 168 个命令后快照，以及 6 组奖励/续层案例。
- 战斗基准逐步比对生命、金币、护盾、各资源、三种牌堆和消耗区、状态、敌人意图、战斗指标、相关随机计数和奖励候选；每一步额外验证 JSON 读档后的下一步结果。
- 战斗参考场景使用明确构造的牌组/收藏品/生命，以覆盖效果和首领意图；不代表完成了整局平衡性或所有组合的验收。
- 仍未同步：事件正文/条件/分支效果、完整商店、休整升级、局外进度/百科行为、统一 GameCommand/DomainEvent 体系、网页 RunSaveV2 互导及正式视觉表现。
- 测试证明上述投影字段一致，不代表完整网页状态和事件日志逐字段一致。安装包尚未重新构建，GUI 视觉效果还需按手动流程验收。
